# ADR 0005: Project rename to coding-stats

## Status: accepted

## Context

The project started as "skill-stats": a tool to mine git history (later
opencode history) for feature-level metrics. The name named the original
motivation (skill-usage stats) rather than the built scope, which is commit
analysis of coding activity. The user decided on the rename to
**coding-stats** in October 2026, including every identity surface.

## Decision

One clean break — no compatibility shims for the tool's own name surfaces:

- **Package, module, CLI**: `skill-stats`/`skill_stats` →
  `coding-stats`/`coding_stats` (pyproject distribution, entry point,
  imports, `uv lock` regenerated).
- **Store**: committed artifact dir `.skill-stats/` → `.coding-stats/`,
  artifact file `skill-stats.sql` → `coding-stats.sql`, artifact header line
  `-- coding-stats artifact`. Old artifacts fail the ingestion header check
  (parse_header demands the current marker line; `gather` refuses them, the
  migration verb reads them past it on purpose) and are regenerated by a
  fresh `update` (the artifact is derived data; its repository key changes
  with the clone URL anyway).
- **CI**: workflow file `coding-stats.yml`, env vars `CODING_STATS_BRANCH` /
  `CODING_STATS_DB`, Actions artifact `coding-stats-report`, bot identity
  `coding-stats[bot]`, commit subject `coding-stats artifact update (auto)`,
  install spec `coding-stats @ git+https://github.com/Dahep/coding-stats.git`.
  The dogfooding scaffold of this repository is swapped in the same change;
  its `uv tool install` pin is `@main` (a sha pin rendered in a PR branch
  would dangle after squash-merge; the tool's own repo is the one case where
  a moving pin is correct).
- **Repo**: GitHub repository `Dahep/skill-stats` renamed to
  `Dahep/coding-stats` after this change merges; local remotes updated.
  GitHub redirects old URLs, so pinned installs in target repos keep
  resolving during the transition. Pages moves to
  `dahep.github.io/coding-stats`.
- **Legacy exclusion**: paths under `.skill-stats/` (any depth) stay excluded
  from analysis beside `.coding-stats/` (ADR-0003 clause 4, now covering both
  names). Pre-rename artifacts are committed in git history forever; excluding
  only the new name would count historical `report.html`/`*.sql` as analyzable
  churn in every repo that dogfooded the old name.
- **Historical records stay verbatim**: ADRs 0001–0004 and
  `docs/decisions-trail.tsv` keep period-correct names and URLs
  (decision-trail entries quote the user and name the PR URLs as they were);
  only normative spec text (ADR-0003 store-path clauses) is updated.

## Consequences

- Target repos with a committed old-format artifact (this repo, `dotfiles`)
  regenerate it under `.coding-stats/` on the next `update`; the old
  directory is then deleted. Until then its history stays excluded, so
  metrics are unaffected.
- Old artifact files are no longer ingestible by `gather` (header check);
  regenerate them.

## Migration of existing users

Per consumer, in dependency order (tool upgrade last — the rename PR ships
the new tool; consumers move after both the merge and the GitHub rename).
The procedure is automated by the `migrate` verb shipped in this same
change, driven from the repository skill
`.agents/skills/migrate-skill-stats/SKILL.md`:

- **CI consumers** (`ci init` was run): the old `skill-stats.yml` keeps
  working through GitHub's redirect — it installs the OLD tool at the pinned
  sha and keeps committing `.skill-stats/` artifacts. It must be deleted and
  re-created from the new tool (`coding-stats ci init`), otherwise a zombie
  pipeline runs forever beside the new one. This repo's own scaffold is
  swapped inside the rename PR; no other repo on this machine has CI.
- **CI stateless DBs**: the workflow's throwaway DB cannot be migrated —
  the first post-upgrade run seeds nothing (no new-format artifact yet) and
  full-recomputes: walk + re-classification of the whole history. One-time,
  bounded (LLM tokens); every later run seeds from the committed
  `.coding-stats/` artifact.
- **Machine-local DBs**: derived data with the verdict cache, and the only
  place verdicts survive. Reusing one avoids the re-classification cost:
  copy the old DB to the new path and run `update`. Two identity rules
  govern which repos can do this:
  - key changes against a DB holding commits are refused by `migrate` itself
    (`identity.register_repository` cannot tell them apart: it refuses every
    kind), EXCEPT the one case the verb is the sanctioned authority for:
    when the legacy artifact digest verifies against the DB (consistency
    under the artifact threat model — the digest is an unkeyed checksum,
    not a forgery proof — so the correspondence is proven), the rename
    case relabels the row to the resolved (post-rename) identity. This
    supersedes the earlier draft rule "the renamed repo's own local DB
    cannot be reused": with correspondence verified, DB reuse is strictly
    cheaper than the fresh-DB full recompute it replaced, and semantically
    the rename changed the URL, not the repository. When correspondence
    CANNOT be proven (mismatched keys, divergent walk coverage), the
    fallback is a fresh DB with a full recompute, as in CI;
  - the legacy DB and the legacy artifact are never silently merged: the
    side that walked/classified ahead wins (the artifact's verdict rows
    travel inside it), so a migration cannot drop classifications a CI run
    landed after the machine-local DB was last touched. Divergent coverage
    is refused outright (which side is authoritative cannot be decided);
  - a canonical → `local:` shim move is only warned about and keeps the
    stored key, so `dotfiles` (keyed on the alias spelling
    `https://github-personal/Dahep/dotfiles@main`, written before the
    ssh-alias-identity fix, #14 — 199 commits, 0 pending verdicts at rename
    time) migrates by DB reuse with a warning.
- **Machine-local state** (`~/.skill-stats/`): DB copies and exported
  reports only — nothing references the path; recreate under
  `~/.coding-stats/` or discard.
- **Pages**: the report URL moves to `dahep.github.io/coding-stats/` with
  the first post-rename deploy; GitHub redirects repository git/API traffic
  on a rename but does NOT redirect Pages sites, so old report links stop
  resolving.
